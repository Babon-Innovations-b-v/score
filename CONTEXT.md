# SCORE — Domain Context

Canonical vocabulary for this codebase: the terms that mean something specific here, each with
the aliases to avoid (`_Avoid_:`). This is the working surface — [`grill`](.claude/skills/grill/)
challenges new terms against it and writes new ones here inline. Glossary only: no implementation
detail, no architecture prose. That lives in [`docs/bible.md`](docs/bible.md).

Format rules: [`.claude/skills/grill/CONTEXT-FORMAT.md`](.claude/skills/grill/CONTEXT-FORMAT.md).

## Language

- **soul** — the checked-in voice spec [`.claude/soul.md`](.claude/soul.md): the rules that fix how the assistant, and therefore most of this project's text, sounds. Every correction to the voice lands here as a rule, and the `UserPromptSubmit` hook in `.claude/settings.json` replays the rules verbatim on every prompt. Treated as a variable to pin down, not a preference. _Avoid_: persona file, style guide, tone guide, system prompt.
- **bible** — [`docs/bible.md`](docs/bible.md), one file, chaptered. The single source of truth for how the system works. _Avoid_: docs, wiki, handbook.
- **PRD** — a GitHub epic issue: one coherent module or workstream, with goal, scope, tasks and a verifiable definition of done. The unit of work and the planning surface. _Avoid_: epic (same thing, one name only), ticket, story.
- **sub-issue** — a task carved out from under a PRD, natively linked so the board nests it. Only for work that is independently grabbable or going `ready-for-agent`; everything else stays a checklist line. _Avoid_: child ticket, subtask.
- **overseer** — the one coordinating session: it runs the work directly by splitting it over many parallel agents, one job each, and checks and merges what they return. It guards drift: it holds the paper, the owner's vision and every standing rule, checks every result against them, spends nothing without the owner and approves nothing on an agent's word. It reports to the owner, who reviews and buys changes in the creator cockpit. _Avoid_: hive, coordinator, lead, captain, main session (main is the branch).
- **captain** — retired 2026-10-18 (owner: "it didnt work"). Was a second session that ran one effort under the overseer; the overseer now runs the work itself. Older records citing "the captain" name decisions taken in that role, and they stand. _Avoid_: using it for anything current; say overseer.
- **agent** — a coding agent the overseer starts for one job with a written brief: it works in its own worktree, tests what it touched, pushes when its checks pass and reports what changed in the result. One agent, one job; work is split across parallel agents by default. It may split its work over sub-agents. _Avoid_: worker, builder, bot.
- **sub-agent** — an agent started by an agent for one narrow step (a search, a render, one fix, a measurement): it returns its result to its parent and never reports to the owner or takes on new scope. _Avoid_: helper, child agent, subtask.
- **overlay** — a per-directory `CLAUDE.md` that the harness auto-loads when a file in that directory is touched. _Avoid_: local rules, sub-config.

## Architecture vocabulary (Pocock's laws)

The core depth/seam vocabulary used by `improve-codebase-architecture`, `tdd`, `diagnose`, `to-prd`. Full definitions: the [`codebase-design`](.claude/skills/codebase-design/SKILL.md) skill.

- **module** — anything with an interface and an implementation. _Avoid_: unit, component, service.
- **interface** — everything a caller must know: types, invariants, ordering, errors, config, perf. _Avoid_: API, signature.
- **implementation** — code inside the module. _Avoid_: internals, body.
- **depth** — leverage at the interface. _Avoid_: thickness, size.
- **deep** — small interface, lots of behaviour behind it.
- **shallow** — interface nearly as complex as the implementation. _Avoid_: thin, anaemic.
- **seam** — where an interface lives. _Avoid_: boundary.
- **adapter** — concrete thing satisfying an interface at a seam. _Avoid_: impl, plugin.
- **port** — interface defined for cross-seam dependencies.
- **leverage** — what callers get from depth. _Avoid_: reuse.
- **locality** — what maintainers get from depth. _Avoid_: cohesion.
- **deletion test** — imagine deleting the module: complexity vanishes → kill; reappears across N callers → deepen.
- **wide layer** — `ls` >12 entries (ignoring build output, caches, `node_modules`, `.venv`, `.git`). Missing boundary. _Avoid_: bloated, junk drawer.
- **split-brain** — same domain in 2+ top-level dirs sharing a name. Fix: pick one home or rename. _Avoid_: scattered, duplicated.
- **deepen** — collapse a wide layer behind ≤7 public symbols; internal files private (`_prefix`).
- **group** — sort a flat pile into named subdirs; no interface change.
- **no-loose-files rule** — every dir = subdirs only, plus a framework carve-out list. ADR-0002 holds the why and the amendment procedure; the authoritative carve-out list is in root `CLAUDE.md`. _Avoid_: top-layer-cleanup, no-floaters.

## Project vocabulary

Carried over from the framework's first user, the game 2099 (its `CONTEXT.md`, 2026-10-02 to 10-08), where these words were sharpened with the owner.

- **SCORE** — the framework, and the paper's name: "SCORE: A Framework for Synthesizing Complete, Owned, Responsive Environments". The creator writes the score; coding agents and open tools play it. Written in capitals. Not WorldScore (a benchmark), not score distillation in text-to-3D, not DeepMind's SCoRe. _Avoid_: Score, the score framework, HAVFM.
- **framework** — SCORE as a whole: the stages, checks, libraries and review tools that turn a creator's picks, offline and in cloud batches, into a fixed, owned, editable environment an engine loads; nothing is generated while the environment is played. An environment synthesis framework, never a world generator. _Avoid_: world compiler, world model (a model that renders frames), pipeline (alone).
- **environment** — the whole thing SCORE makes from one creator's picks: its places, their layers and the library they are painted and filled from, kept as one record the runner drives (`python -m score run <environment>`). Stored ids keep their old spelling (`world1` is environment 1's id; the store's keys and records say world), and so does a node's grain `world` in the runner's keys, because renaming either would make every accepted node again. Not the `Environment` prim of a place's OpenUSD stage (its sky light and haze). _Avoid_: world, level, map, scene (alone).
- **route** — the sequence of stages one place is built through, with its rules and checks; its order is shapes first, the same loop at every scale. _Avoid_: workflow (alone), recipe, pipeline (alone).
- **place** — one part of an environment with a look of its own (a room, the ground round a base, a ship), built by one run of the route. An outside place sits in the environment; an inside place sits within an outside shell, its shape split from that shell's plan. _Avoid_: level, location, area, zone, sub-place.
- **shapes first** — the route's one loop, the same at every scale: first the big shape, a place's outside shell, gets its concept, its plan and its rough model, which gives the plan its proportions; then the plan splits the shell into the shapes of its inside places (rooms, corridors, holds), each sized inside the shell; once those shapes are fixed, every place's concept, rough model, close-ups and finishes are made in parallel, because from then on each is proportions inside a fixed shape. Zooming into an inside place repeats the same steps. The owner's rule of 2026-10-19. _Avoid_: outside first, outside then inside, inside out, room by room, top-down pass, nesting.
- **outside shell** — the big shape of a place that holds inside places (a ship's hull, a base's outer wall): the first thing the loop decides, and the size every inside place's shape is fitted into. _Avoid_: exterior, hull (alone: the ship's own word), envelope, box, big shape (say outside shell).
- **inside place** — a place whose shape is split from an outside shell's plan (a room, a corridor, a hold) and sized inside that shell; its concept is drawn to that shape once the shapes are fixed, never before. _Avoid_: room (alone: not every inside place is a room), interior, child place, sub-scene.
- **rough model** — a place's concept put through the prop pipeline whole: one 3D model that gives the plan its proportions and shape; never shipped. _Avoid_: blockout, greybox, massing model, rough plan (the plan drawn to it is the plan).
- **neighbour** — another place a place shows (the square and the far city past the launch), listed in its scene record's `places` and stood in its stage as that place's own accepted assembly, without the neighbour's own neighbours. _Avoid_: adjacent place, linked place, sub-scene.
- **motion** — the one layer for everything in a place that moves: people and animals, moving objects (a rover's wheels, a hatch on its hinge, a ferry on its lane, a boom on its rail), plants that grow and sway, and real physics (settling, falling, cloth). Every model still comes from the prop pipeline; motion adds the rest as connected modules: rigging (UniRig), body reading (SAM 3D Body), generated body motion (Kimodo), joints and paths for rigid parts, growth and sway, and physics simulation, checked by the motion check (#23). Real physics-based movement is a goal of the framework (the owner, 2026-10-20). _Avoid_: mover, machine, animation, animated prop, actor.
- **concept** — a picture of a place drawn from the creator's references and picked by the creator; it sets the place's structure and look and is never shipped. An inside place's concept is drawn to its shape from the outside shell's plan, so it fits that shell. _Avoid_: key art, mockup, target (alone).
- **scene inventory** — the hard list of exactly what is in a place: every object a row with a kind, an anchor, a size in metres and a count, children anchored on their parent. Nothing is made or placed that is not a row. _Avoid_: object list, manifest, asset list.
- **close-up** — one clean, front-on picture of one object, drawn from its inventory row; the input to the prop pipeline and to the parts check. _Avoid_: crop (a crop is cut from a bigger picture), reference image.
- **code builder** — code a coding agent writes that builds one kind of object exactly (a wall plate, a door, a tool board). _Avoid_: procedural asset, handcrafted model.
- **scene record** — a place's record of what no made piece covers (shells, stairs, gameplay objects, ground and water, backdrop, lights, sky, the neighbours it shows) and the cameras it is judged from, as numbers its code builders and the stage read; written by the scene-record stage from the place's plan (environment 1's first records were transcribed from the game, and are now seeds). _Avoid_: scene file, extras, game-only layer.
- **plan** — a place's dimensioned drawing in metres (`data/plans/<place>.json`): its walls, doors and where each leads, its items with the inventory rows that make them, its keep-clear zones and standing spots, and its concept read element by element, drawn to its rough model's proportions. An outside shell's plan also splits the shell into the shapes of its inside places. _Avoid_: layout (the inventory's laid spots), floor plan (the owner's word for the same thing), blueprint.
- **prop pipeline** — the one channel every object and shell piece is made through (the owner, 2026-10-20, #19); its gates decide what more a model needs (a code body for a big object, code only on a named failure). The route's picture-to-3D branch: close-up, Pixal3D in a cloud batch, closed into a solid, triangles by size, straightness check. The same picture-to-model step turns a whole concept into a place's rough model. _Avoid_: generator, AI model step.
- **layer adapter** — what a layer that needs models adds around the prop pipeline, which still makes every model: its own inputs (which rows, close-up wording, poses or growth stages) and its own steps and checks after the model (rigging and motion for people, joints and paths for rigid moving things, growth for plants). Terrain is a model layer too: its concept goes through the prop pipeline as its rough model, then close-ups of its detail areas, the same shapes-first loop as a building. A layer without models (light, sound, sky, films) has its own route instead, under the same batch rules (the owner, 2026-10-20). _Avoid_: plugin, branch, custom pipeline, side route.
- **parts check** — the rule that routes a kind: the prop pipeline first for every object and shell piece; built in code only when the prop pipeline fails on that object, the failure named in its record (the owner, 2026-10-20, #19; until #19 lands the sorter still builds in code a kind whose code build shows every part its close-up shows). _Avoid_: sorter (the sorter is the tool that applies it), shape rule.
- **shell section** — a stretch of a room's walls, floor or ceiling that its plan marks as one type, as the concept shows it: one piece style and one finish, with wear and dirt running across the seams of its joined pieces. A cabin may be one section, a hangar several; the look changes only between sections. _Avoid_: zone, area (a place), tile set, wall type.
- **surface library** — the one shared set of rule-based surfaces (ProcFunc functions, coloured from palette tokens, wear and seed as settings) every part of every piece is painted from; models and code give shape only. _Avoid_: material library, texture set, trim sheet.
- **finish map** — a flat-colour copy of a model's close-up: the same outline and framing, every finish one solid label colour on a plain background, each label tied to one surface of the surface library; used to split the model into parts by finish. _Avoid_: label map, segmentation mask, colour map, part map (a part map shows the split itself).
- **room wear** — the one wear setting a room's surfaces share, with wear from a cause (edges, feet, drips). _Avoid_: weathering, dirt pass.
- **walkable reference** — the optional stage that turns a picked concept into a walkable whole-room reference for later stages; never shipped, and not the rough model (that is the loop's own step, made by the prop pipeline). World Labs Marble (the product's own name, kept) in our runs; never compared with another model. _Avoid_: world step (the older word), plan world (2099's), world model.
- **review tools** — what SCORE gives the creator to judge a place: pages with each stage's outputs side by side, before and after shots from the same cameras, in-engine walkthroughs and every check's result. How the creator judges with them is the creator's own. _Avoid_: blind pick, vote, approval gate.
- **creator cockpit** — the one signed-in web page the creator runs SCORE from: his environments, each split by engine, then style, then place, layer and step, where he inspects outputs, asks for changes, advances steps, buys his basket and launches work against his stop. It reads the runner and the review tools and judges nothing itself. _Avoid_: dashboard, admin panel, UI, control panel, web app.
- **basket** — what the creator buys in the creator cockpit, item by item: each item is one change, and opens to details that are free and fast to make (before and after from the same cameras, a 3D look, what moves and its price) and show what buying it would change; buying the basket is the creator's one money yes. The owner's rule of 2026-10-19. _Avoid_: proposal (retired as the creator's word; the cockpit's `proposals/` code makes an item's details), shopping list, cart, changes to buy, order.
- **batch** — one shot of paid work the creator said yes to, at any layer: one spend estimate and one ETA given before it starts; the creator's yes to that estimate is the only spend decision, and the batch's stop is its own high estimate plus a 10% buffer, never a separate figure he sets (the owner, 2026-10-20); every job run once, no reruns or retry loops inside it. Its checks only sort each output into a success or a named failure mode; a failure becomes a gap, and any new spend on it is a new batch and a new ask. All the risk work happens before the batch, free: predictions and preparations that make it right the first time (the owner, 2026-10-20). _Avoid_: run (alone), job (one task inside a batch), retry, loop.
- **basket item** — one change in the basket (a fix branch for one place), priced by the runner, with its free details. _Avoid_: proposal, card, line, offer.
- **film script** — a film's ordered list of segments on one timeline, kept as data, one file a film (`data/films/<film>.json`): each segment says what it shows (the environment, a place, a layer, a part or piece), its cut type (walk-through, orbit, hero still, exploded view, isolate, layer focus, layer split, step card, before and after, title or text card), its length in seconds, its transition and its sound. The creator writes it in the creator cockpit and plays it there for free on the places' 3D web copies and existing films; it compiles to render items (the frames still to make, the films reused) priced before anything is bought. A demo film is a sales trailer for the environment, so the script gives the finished places the time. _Avoid_: storyboard, shot list, edit decision list, EDL, cut list, timeline (alone).
- **picked viewpoint** — a view the creator saved while walking a place in the viewer (eye, aim, fov, a name), kept in `data/review/<place>/viewpoints.json`; a place's films start from its picked viewpoints when it has any. _Avoid_: bookmark, saved camera, pick (alone: a pick is a model the creator chose for a row).
- **capability class** — what a cloud job needs from a machine, named without a provider: `gpu-<GB>gb` (one card with that much memory), `gpu-<GB>gb-x<N>` (N such cards), `cpu-<cores>c-<GB>gb` (a processor machine). Runners ask for classes; the cloud backend maps each to its own machine types. _Avoid_: machine type, instance type, card type (these are a provider's names).
- **parked machine** — a machine kept after its run (its files removed, its set-up kept) for the next run of the same kind to take instead of renting (`tools/props/cloud/park.py`): a processor machine billed by the started hour until 5 min before its paid hour ends, a card for its kind's measured cold start (at most 10 min). Never idle past that. _Avoid_: warm machine, warm card, pool, kept machine.
- **cloud backend** — one cloud provider behind the framework's provider interface (`tools/props/cloud/provider.py`), holding that provider's machine types, zones, prices, secret store and self-delete. Scaleway is the current one. _Avoid_: cloud (alone), provider module, Scaleway (for the interface).
- **character** — a person or animal in a place, made from the place's data, rigged and playing a clip: a skinned UsdSkel asset in the place's stage. _Avoid_: NPC, actor, avatar, agent (an agent is a coding agent).
- **cast** — the record of a place's characters, `data/characters/<place>.json`: who is there, how many, where, doing what, and why each is there; nothing is placed that is not an entry. _Avoid_: spawn list, population, NPC list.
- **crowd** — many copies of one cheap character body in a few clips, phases and palettes of clothes, laid as one instancer; anybody within reach of the viewer is a character of their own instead. _Avoid_: extras, background people, swarm.
- **stage** — one fixed step of the route, with a stated input and output, gates and a review page (concept, plan, inventory, layout, assembly, settle, the layers, complete; close-up, shape, parts, surfaces per object). A row of the stage table in `score/stages`. _Avoid_: step (alone), phase, task.
- **runner** — SCORE's engine, the `score` command: it walks the stage table for an environment, works out each node's key from its code and inputs, finds what is already made and accepted in the store, prices and times what is missing, runs the rest (paid nodes on rented cloud machines, in a batch the creator said yes to), judges each output with its gates and records it. It decides nothing about taste; the creator cockpit shows what it reports. _Avoid_: pipeline (alone), orchestrator, scheduler, engine (the game engine).
- **node** — one stage for one place (`assembly@hangar`), or for the whole environment (its grain is still called `world` in the keys); what the runner keys, makes, judges and accepts. _Avoid_: job (a job is a cloud run), target, asset.
- **finish record** — what a node's run leaves in the store: its key, output, every input's hash, its code version, commit, seed, parameters, machine, time and cost. No record counts as not run. _Avoid_: log, manifest, run info.
- **gate** — a stage's check between it and the next: it answers pass, fail or unknown with measures and a reason; unknown blocks like fail, and missing evidence is unknown. _Avoid_: test, validation, guard (a guard is a hook).
- **accepted output** — the output of a node that stands accepted; the only one later stages read. The runner accepts an output by itself when every gate passed and no score got worse (an automatic accept, its record says so); the owner may reject any accepted output, which moves it back to the one accepted before and makes every later node that read it stale, or accept a worse one with his reason. _Avoid_: canonical, latest, current take, approved.
- **clearance** — the runner's leave for one paid run of a node: given when every gate on its inputs passed and they stand accepted, the month's books are known, and its batch's stop (or a benchmark grant) has room for its forecast; there is no month's ceiling (owner, 2026-10-20); kept in the store, and the only thing besides the owner's override that lets a rent point spend. _Avoid_: spend yes (that is the owner's override), approval, budget.
- **unverified seed** — an old output brought into the store as a stage's output (hashed, its origin shown) that no gate has judged yet; never accepted until its stage reruns or checks it. _Avoid_: legacy output, baseline, import.
- **contract** — a stage output's schema, version and units (metres, seconds, degrees, Y up), stamped into the output as `contract.json`, checked by the stage that makes it before it is stored and by every stage that reads it. _Avoid_: format, spec, interface (an interface is a module's way in).
- **quality score** — a library entry's 0 to 100, made of named parts that a scoring system of its own kind measures free and locally (a model's geometry, finish and likeness; a sound's prompt match, loudness and clipping), 50 being a gate's line where a gate measures the part; an assessment for choosing what to refine, never a gate. _Avoid_: score (alone: the framework's name), rating, grade, quality (alone).
- **waiver** — the owner's word that one check of one node counts as passed under one key, with his reason; it ends when the key changes and shows on the review page and in status. _Avoid_: override, exception, skip.
- **gap** — something a place still lacks or that fails a check, shown in its OpenUSD scene: a scene inventory row with nothing made for it, a made object that fails a gate, a route step the place has not been through, or a lost input. What a place needs comes only from its concept and the scene inventory drawn from it. A gap is **open** (still to be made or fixed; priced and in the basket) or **accepted** (the creator decided to ship with it, written in `data/checks/gaps/<place>.json` with who decided, when, why and the measured faults; the completion gate lists it but does not block on it; never a loosened gate). The owner, 2026-10-20: one word for both, in code, data and the cockpit too (#41). _Avoid_: hole, named gap, missing item, todo, waiver (a waiver passes a check), known issue.
- **complete** — a place's status when every requirement of its completion gate passes and it has no gap. _Avoid_: done, finished, shipped.
- **complete apart from accepted gaps** — a place's status when its accepted gaps are the only requirement that fails: the gate lists every gap with its numbers and who decided it, and the run passes. _Avoid_: mostly complete, complete with gaps, partly done.
- **NOT complete** — a place's status when any other requirement fails or is unknown. _Avoid_: incomplete, failed, blocked.
- **shell split** — the route's step between an outside shell's rough model and its inside places: the shell's plan cut into the shapes of its inside places (rooms, corridors, holds), each sized inside the shell, tiling its inside with no overlap and every one reached through doors; the stage `shell-split` (`score/stages/shell_split`), whose output every inside place's own route reads. _Avoid_: floor plan (the owner's word for a plan), room split, partition (the concept partition is the picture's), subdivision.
- **finish route** — the library-first way a model gets its finishes (owner, 2026-10-20): the model rendered from every angle a free coverage check needs, one batch answer a model giving its finish list (each finish first matched to a surface of the surface library with its settings: palette token, shine, seed; wear stays the place's level) and a label for each colour region of each view, the model split by those labels voting across views (an unassigned face or views that disagree is a gap), each part given its surface, and one batch recheck against the close-up that only sorts pass or the named fault "no library surface fits". The place lines' surface route since 2026-10-20 (#18); rows `finish-route-*` and `surfaces-parts`, `-paint`, `-bake`, `-check` in `score/stages/surfaces`. _Avoid_: paint pass, texturing, finish-map method (the earlier route, kept by the crops' and people's lines).
- **stand-in close-up** — what the finish route shows in place of a model's close-up when its own is not there: the model's own texture drawn from the front. Always named a stand-in; a recheck against it says so. _Avoid_: close-up (alone, for it), reference render, fake close-up.
