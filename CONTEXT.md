# SCORE — Domain Context

Canonical vocabulary for this codebase: the terms that mean something specific here, each with
the aliases to avoid (`_Avoid_:`). This is the working surface — [`grill`](.claude/skills/grill/)
challenges new terms against it and writes new ones here inline. Glossary only: no implementation
detail, no architecture prose. That lives in [`docs/bible.md`](docs/bible.md).

Format rules: [`.claude/skills/grill/CONTEXT-FORMAT.md`](.claude/skills/grill/CONTEXT-FORMAT.md).

## Language

- **soul** — the checked-in voice spec [`.claude/soul.md`](.claude/soul.md): the rules that fix how the assistant, and therefore most of this project's text, sounds. Every correction to the voice lands here as a rule, and the `UserPromptSubmit` hook in `.claude/settings.json` replays the rules verbatim on every prompt. Treated as a variable to pin down, not a preference. _Avoid_: persona file, style guide, tone guide, system prompt.
- **bible** — [`docs/bible.md`](docs/bible.md), one file, chaptered. The single source of truth for how the system works. _Avoid_: docs, wiki, handbook.
- **PRD** — a GitHub epic issue: one coherent module or workstream, with goal, scope, tasks and a verifiable definition of done. The unit of work and the planning surface. _Avoid_: epic (same thing, one name only), ticket, story.
- **sub-issue** — a task carved out from under a PRD, natively linked so the board nests it. Only for work that is independently grabbable or going `ready-for-agent`; everything else stays a checklist line. _Avoid_: child ticket, subtask.
- **overseer** — the one coordinating session: it runs the work directly by splitting it over many parallel agents, one job each, and checks and merges what they return. It guards drift: it holds the paper, the owner's vision and every standing rule, checks every result against them, spends nothing without the owner and approves nothing on an agent's word. It reports to the owner, who reviews and buys changes in the creator cockpit. _Avoid_: hive, coordinator, lead, captain, main session (main is the branch).
- **captain** — retired 2026-10-18 (owner: "it didnt work"). Was a second session that ran one effort under the overseer; the overseer now runs the work itself. Older records citing "the captain" name decisions taken in that role, and they stand. _Avoid_: using it for anything current; say overseer.
- **agent** — a coding agent the overseer starts for one job with a written brief: it works in its own worktree, tests what it touched, pushes when its checks pass and reports what changed in the result. One agent, one job; work is split across parallel agents by default. It may split its work over sub-agents. _Avoid_: worker, builder, bot.
- **sub-agent** — an agent started by an agent for one narrow step (a search, a render, one fix, a measurement): it returns its result to its parent and never reports to the owner or takes on new scope. _Avoid_: helper, child agent, subtask.
- **overlay** — a per-directory `CLAUDE.md` that the harness auto-loads when a file in that directory is touched. _Avoid_: local rules, sub-config.

## Architecture vocabulary (Pocock's laws)

The core depth/seam vocabulary used by `improve-codebase-architecture`, `tdd`, `diagnose`, `to-prd`. Full definitions: the [`codebase-design`](.claude/skills/codebase-design/SKILL.md) skill.

- **module** — anything with an interface and an implementation. _Avoid_: unit, component, service.
- **interface** — everything a caller must know: types, invariants, ordering, errors, config, perf. _Avoid_: API, signature.
- **implementation** — code inside the module. _Avoid_: internals, body.
- **depth** — leverage at the interface. _Avoid_: thickness, size.
- **deep** — small interface, lots of behaviour behind it.
- **shallow** — interface nearly as complex as the implementation. _Avoid_: thin, anaemic.
- **seam** — where an interface lives. _Avoid_: boundary.
- **adapter** — concrete thing satisfying an interface at a seam. _Avoid_: impl, plugin.
- **port** — interface defined for cross-seam dependencies.
- **leverage** — what callers get from depth. _Avoid_: reuse.
- **locality** — what maintainers get from depth. _Avoid_: cohesion.
- **deletion test** — imagine deleting the module: complexity vanishes → kill; reappears across N callers → deepen.
- **wide layer** — `ls` >12 entries (ignoring build output, caches, `node_modules`, `.venv`, `.git`). Missing boundary. _Avoid_: bloated, junk drawer.
- **split-brain** — same domain in 2+ top-level dirs sharing a name. Fix: pick one home or rename. _Avoid_: scattered, duplicated.
- **deepen** — collapse a wide layer behind ≤7 public symbols; internal files private (`_prefix`).
- **group** — sort a flat pile into named subdirs; no interface change.
- **no-loose-files rule** — every dir = subdirs only, plus a framework carve-out list. ADR-0002 holds the why and the amendment procedure; the authoritative carve-out list is in root `CLAUDE.md`. _Avoid_: top-layer-cleanup, no-floaters.

## Project vocabulary

Carried over from the framework's first user, the game 2099 (its `CONTEXT.md`, 2026-10-02 to 10-08), where these words were sharpened with the owner.

- **SCORE** — the framework, and the paper's name: "SCORE: A Framework for Synthesizing Complete, Owned, Responsive Environments". The creator writes the score; coding agents and open tools play it. Written in capitals. Not WorldScore (a benchmark), not score distillation in text-to-3D, not DeepMind's SCoRe. _Avoid_: Score, the score framework, HAVFM.
- **framework** — SCORE as a whole: the stages, checks, libraries and review tools that turn what a creator locks, offline and in cloud batches, into a fixed, owned, editable environment an engine loads; nothing is generated while the environment is played. An environment synthesis framework, never a world generator. _Avoid_: world compiler, world model (a model that renders frames), pipeline (alone).
- **environment** — the whole thing SCORE makes from what one creator locks: its scenes, their layers and the library they are painted and filled from, kept as one record the runner drives (`python -m score run <environment>`). Stored ids keep their old spelling (`world1` is environment 1's id; the store's keys and records say world), and so does a node's grain `world` in the runner's keys, because renaming either would make every accepted node again. Not the `Environment` prim of a scene's OpenUSD stage (its sky light and haze). _Avoid_: world, level, map.
- **route** — the sequence of stages one scene is built through, with its rules and checks; its order is shapes first, the same loop at every scale. _Avoid_: workflow (alone), recipe, pipeline (alone).
- **scene** — what the creator designs: one part of an environment with a look of its own (a room, the ground round a base, a ship), built by one run of the route (the owner, 2026-10-21: scene replaces place). Scenes are layered the way studios layer them in OpenUSD: a scene sits within its parent scene, and the scenes within it are its child scenes; a top scene sits in the environment itself. A scene is its outside, with one concept; the scenes inside it are its child scenes, never a separate "outside" of the same scene (the owner, 2026-10-20). A thing in a scene, even one that moves (the garage's door leaves), is an object of it, an inventory row, never a scene of its own (owner, 2026-10-20). Code identifiers, paths and stored ids still say place (`<place>`, `assembly@hangar`'s grain) until the restructure pass. _Avoid_: place, level, location, area, zone, sub-scene, door kit.
- **shapes first** — the route's one loop, the same at every scale: first the big shape, the parent scene, gets its concept, its plan and its rough model, which gives the plan its proportions; then the plan splits the parent scene into the shapes of its child scenes (rooms, corridors, holds), each sized inside it; once those shapes are fixed, every scene's concept, rough model, close-ups and finishes are made in parallel, because from then on each is proportions inside a fixed shape. Zooming into a child scene, now a parent scene of its own, repeats the same steps. The owner's rule of 2026-10-19. _Avoid_: outside first, outside then inside, inside out, room by room, top-down pass, nesting.
- **parent scene** — the scene a scene sits within; seen from its child scenes, the big shape that holds them (a ship's hull, a base's outer wall): the first thing the loop decides, and the size every child scene's shape is fitted into (the owner, 2026-10-21). _Avoid_: outside shell, outside place, exterior, hull (alone: the ship's own word), envelope, box, big shape, holder.
- **child scene** — a scene that sits within its parent scene, its shape split from the parent scene's plan (a room, a corridor, a hold) and sized inside it; its concept is drawn to that shape once the shapes are fixed, never before (the owner, 2026-10-21). _Avoid_: inside place, room (alone: not every child scene is a room), interior, child place, sub-scene.
- **scene tree** — a scene with every child scene its plan lays out standing at its spot, each child its own tree in turn: in OpenUSD the scene's assembly referencing each child's own tree at the child's outline on the parent's plan, so opening a top scene opens everything within it while each child stays its own layer stack, made, checked and changed apart (`scene-tree@<scene>`, 2026-10-21). _Avoid_: hierarchy, nesting, scene graph, world assembly, set.
- **shared room** — one child scene made from two whose shapes the creator overlapped on their parent scene's plan (the owner, 2026-10-21: "if u overlap it becomes shared rooms"; the cockpit and the navigation module became "Cockpit and nav"): one shape round both, named from both, keeping the id of the one dropped on, the other no scene and no card any more; said with an undo, and its draws out of date like any room the plan above changed. _Avoid_: merged scene, combined room, joint room.
- **thing in a room** — a box the creator dropped fully inside a child scene's shape on its parent scene's plan (the owner, 2026-10-21: the nav module in the middle of the cockpit and nav): something standing in that child scene, kept with its shape on the plan at its spot and size, no scene and no card of its own; its draw wording names it and where it stands. Once that child scene's concept is read, what it shows is an object of its scene inventory like any other. _Avoid_: sub-scene, nested scene, prop (the prop pipeline's word), object (alone: an inventory row).
- **top scene** — a scene with no parent scene, sitting in the environment itself on its own site of the environment plan (the owner, 2026-10-21). _Avoid_: outside place, top place, root scene.
- **rough model** — a scene's concept put through the prop pipeline whole: one 3D model that gives the plan its proportions and shape; never shipped. The one way a scene's rough shapes are made (the owner, 2026-10-23: no blockout, a grey model built in code before the concept, retired: "we have the prop pipeline to get the rough shapes first anyway"). _Avoid_: greybox, massing model, blockout, rough plan (the plan drawn to it is the plan).
- **neighbour** — another scene a scene shows (the square and the far city past the launch), listed in its scene record's `places` and stood in its stage as that scene's own accepted assembly, without the neighbour's own neighbours. _Avoid_: adjacent scene, linked scene, sub-scene.
- **physics setup** — a library entry holding one reusable setup for the physics simulation (the owner, 2026-10-20): a body's weight and joints, a hinge or rail with its limits and motor, a settle or snap rule, a planet's gravity and the bodies it holds in orbit; the motion layer places it on a scene's models. The library's Physics shelf holds only these; the library's one other code is the surface recipes, on Surfaces. A layer's placement, layout, terrain, sky, light, sound and film code is the framework's own steps, never a library entry (the owner, 2026-10-21). _Avoid_: algorithm, physics layer, rig.
- **motion** — the one layer for everything in a scene that moves: people and animals, moving objects (a rover's wheels, a hatch on its hinge, a ferry on its lane, a boom on its rail), plants that grow and sway, and real physics (settling, falling, cloth), up to the worlds themselves: each world, the sun and every other body in a scene's sky is a moving object the environment's physics drives (orbits, spin, day and night, phase), never a painted backdrop (the owner, 2026-10-21). Every model still comes from the prop pipeline; motion adds the rest as connected modules: rigging (UniRig), body reading (SAM 3D Body), generated body motion (Kimodo), joints and paths for rigid parts, growth and sway, and physics simulation, checked by the motion check (#23). Real physics-based movement is a goal of the framework (the owner, 2026-10-20). _Avoid_: mover, machine, animation, animated prop, actor.
- **concept** — a picture of a scene drawn from the creator's references and locked by the creator; it sets the scene's structure and look and is never shipped. Every concept is drawn from one fixed viewpoint (the owner, 2026-10-20): a top scene from a high three-quarter view from one corner, about 35 to 45 degrees down, the whole scene in frame, a long lens, readable light; a child scene as a cutaway from the same view; one 16:9 picture, no text, people for scale. Once locked it is handed over to score_lib, as is every locked close-up (the owner, 2026-10-20), so no work folder holds the only copy. A child scene's concept is drawn to its shape from the parent scene's plan, so it fits its parent scene. Every scene's concept is drawn by one rule, layer by layer (the owner, 2026-10-20): its own look, its own doors and openings as its plan lays them and no others, its size against the scenes beside it in relative words, the scenes listed inside it named and joined as the creator laid them, the creator's own words and references for it; a child scene is drawn on a crop of its parent scene's locked concept showing only what holds it (the ship for its rooms, the block for the flat), never the whole parent scene or a view round it, as one of a list every child scene of the same parent shares word for word ("the ship is divided into these compartments: 1. cockpit, 2. ...; this concept is number x"), its inside alone: its own walls, floor, ceiling, doors and furniture, its windows glass on a plain dark backdrop, no hull and nothing outside (the owner, 2026-10-21); and only once that one is locked (the lock is the approval), its scene inventory read and its plan made (the owner, 2026-10-21), and on the locked concept of each scene beside it that it opens into, so their shared door matches. A part of a scene's outside (the Square's launch) has no concept of its own. _Avoid_: key art, mockup, target (alone).
- **lock** — the creator's choice of one draw as a scene's concept, with the Lock button on its concept review (the owner, 2026-10-21: "change the word pick to lock everywhere"): the locked concept is the one every later step reads, and the lock is his approval of it, never followed by a second one: its scene inventory and then its plan follow on their own. He may unlock it to mark and draw again until its design is approved (its scene inventory read and its plan made); a new lock puts what was read and planned from the old one out of date. The environment concept is locked and unlocked the same way, its unlock asking twice because it puts every scene's concept made from it out of date. Stored ids and code keep the old word (`picks/` records, `concept-pick` requests, `picked_of`). Not the pick lock of a row's model (`tools/usd/picks.py`: the model the creator chose for an inventory row, which keeps the word pick). _Avoid_: pick, picked, choose, select, approve (for a concept).
- **scene inventory** — the hard list of exactly what is in a scene: every object a row with a kind, an anchor, a size in metres and a count, children anchored on their parent. Nothing is made or placed that is not a row. An object is a row only where both readers agree, Gemini naming it and SAM 3 finding it, its count the instances found; what only one of them saw is skipped, kept beside the inventory and never a row or a gap; the scene's structure and ground (walls, floors, shells, terrain, sky, a part holding a child scene and what stands in it) is kept as read (the owner, 2026-10-21). It is read from the scene's locked concept, starting the moment the creator locks it; a scene whose concept is not locked has no scene inventory, and one made from an older concept is out of date and counts for nothing (the owner, 2026-10-20). _Avoid_: object list, manifest, asset list.
- **row kind** — what a scene inventory row's objects do in their scene, worked out free from the reading's own words (its noun) by one table of rules (`data/checks/row-kinds.json`, `score/stages/row_kinds.py`): it emits (an effect), moves (a rigid move), is loose (dropped and pushed in the physics trial), glows (a lamp), shows (a screen), grows (a plant), acts (a person) or roams (an animal: a body row and a clips row of its own, `score/stages/animals`). The effects, motion and physics layers take their work from it and from the design, never from a record written per scene (the owner, 2026-10-21: "the modules are not agnostic"), and which layers a scene has follows from it alone (`score/stages/design_layers.py`: one answer for the stage table and the assembly's layers gate). Not the row's `kind` field, which is how it is made (code or generate). _Avoid_: role, category, type.
- **plant** — a scene inventory row whose row kind grows (a tree, a palm, a shrub, moss, a potted plant, the plants on a bed), each a model of the prop pipeline like any other; the Buy screen counts every plant of the design (`design_layers.plants_of`), so the crops' few steps are never read as the plants (the owner, 2026-10-24, on "Crops 3": "shouldnt these be called plants; and doesnt env 1 have way more plants"). _Avoid_: vegetation, greenery, foliage, crops (for plants in general).
- **crops** — the plants a scene grows on its beds (a growing row standing on a bed, or on a planter), laid many times over the plan's beds at the spacing measured on the concept: the crops layer (`score/stages/crops`, rows `crops-*`), the motion layer's growth module. A potted plant or a tree is a plant, never a crop. _Avoid_: field, garden, plants (for the bed layer alone).
- **close-up** — one clean, front-on picture of one object, drawn from its inventory row; the input to the prop pipeline and to the parts check. _Avoid_: crop (a crop is cut from a bigger picture), reference image.
- **code builder** — code a coding agent writes that builds one kind of object exactly (a wall plate, a door, a tool board). _Avoid_: procedural asset, handcrafted model.
- **scene record** — a scene's record of what no made piece covers (shells, stairs, gameplay objects, ground and water, backdrop, lights, sky, the neighbours it shows) and the cameras it is judged from, as numbers its code builders and the stage read; written by the scene-record stage from the scene's plan (environment 1's first records were transcribed from the game, and are now seeds). _Avoid_: scene file, extras, game-only layer.
- **physics** — what everything in an environment stands on and in, and how it moves (the owner, 2026-10-21: physics replaces setting), at the scale the creator sets, decided in its environment concept (the owner, 2026-10-21: "an environment can be a planet, a system of planets, or just a house on some terrain"): its bodies, each optional (a star, worlds, moons that move one another: a real one named takes its values from the cited reference table of real bodies, an invented one is given by its radius, mass and so gravity, orbit and spin), its plots (flat ground with a gravity, no body under it) and each top scene's site (latitude, longitude and height on a body, its ground curving with the body's true radius; metres on a plot). Each thing in it is present in the form its scale calls for, never a fixed "sky" (the owner, 2026-10-21): a body near enough to matter moves in the physics simulation (one that shines gives its light, falling off with distance); a far source of light is a light, with its colour, strength and path over the day (one house's sun is just a big light); what is too far to move is a backdrop (the stars, a light-giving dome around everything; a distant skyline). The same data drives what is seen overhead and the motion. _Avoid_: setting, physics engine (an engine is the game engine), world (alone), worlds (for the whole), universe, world settings, map.
- **environment concept** (EC) — what the creator locks down for a whole environment before any scene is drawn: its style and its physics, with his reference pictures. The EC holds the scenes and their layering, its top scenes and the child scenes each may hold; for each scene a concept is then locked, in order of parent scene and child scene (the owner, 2026-10-21). Made in a short set interview with a model in the creator cockpit, then locked by him; every scene's concept is drawn from it. Unlocking it puts every scene's concept made from it out of date, so it asks twice. Not a scene's concept (that is a picture). _Avoid_: environment brief, setup, onboarding, world settings.
- **environment plan** — the environment's own plan, the first parent's (the owner, 2026-10-21): one map a ground of its physics, each top scene's site on it (where the physics puts it; its footprint, size and blocks its top scene's own plan, never written apart, so the two never differ (the owner, 2026-10-23); the ground and terrain heights round it; its scene time), the true distances between sites on the same ground (two that would overlap parted along their bearing, unless the creator placed both himself), and the physics from which what each site sees overhead at its scene time is worked out: every other body at its true direction, size and phase, lit from its star, a moving body the physics drives, every light and backdrop, never a fixed sky. Its grounds, sites and sizes come from its physics, never from the game (the owner, 2026-10-21). Written by the same plan writer as a scene's plan; shown and fixed on its plan page; one made under another version of the environment concept is out of date. _Avoid_: world map, site plan (alone), sky settings.
- **design** — a scene's concept and its plan (a scene is one parent scene or one child scene, so one concept each; a child scene's design follows its parent scene's), decided by the creator before any batch (the owner, 2026-10-20): drawn, then fine-tuned wherever the creator wants, until he locks it. The lock is his approval (the owner, 2026-10-21): the scene inventory and then the plan follow from it on their own, open for him to inspect and fix, never a second approval; a child scene within it can be drawn only once it is locked, inventoried and planned. Only an approved design starts a batch, and that batch runs on its own from the design to a finished scene, with no further stop for the creator. _Avoid_: sign-off, pre-production, setup.
- **concept review** — the creator's page for one scene's concept that is not yet locked (the owner, 2026-10-20): opened from the scene's card, he highlights areas and notes what to change, and asks for a new draw from there; each draw is one direct model call priced on the button, his click its spend yes, outside any batch (the batch rules start after the design is approved). _Avoid_: concept editor, concept batch, feedback loop.
- **discussion** — on a concept review, the creator's questions about the draw shown and the prompt model's plain answers, asked with Discuss before he draws again (the owner, 2026-10-21): each Discuss sends what a redraw would (the picture, his marks and notes, the pictures it is drawn on, its prompt) with the discussion so far and his note as the question, one paid call priced on the button, his click its spend yes. It stays open until the next draw of the scene: that draw's prompt rewrite gets it with his notes, and from then on it is closed, kept for the record. _Avoid_: chat, conversation, thread (for the record), feedback.
- **plan review** — the creator's page for one scene's plan (the owner, 2026-10-21): the plan drawn top down beside the locked concept, made automatically from the lock and its scene inventory; he inspects and fixes it (moves and resizes items and child scenes, moves doors, adds, removes or renames child scenes, marks and notes the prompt model corrects it by, priced on the button), his edits kept as his own and redoing what follows. It has no approval of its own: the lock is. _Avoid_: plan editor, floor planner, plan approval.
- **plan** — a scene's dimensioned drawing in metres (its kept plan, `{home}/design/plans/<place>.json`: his edit, else the written plan; the filed `data/plans` of the old concepts were retired 2026-10-21): its walls, doors and where each leads, its items with the inventory rows that make them, its keep-clear zones and standing spots, and its concept read element by element, drawn to its rough model's proportions. A written plan is measured off a top-down drawing of its locked concept (the concept redrawn from directly above, same layout), never packed from words, and its arrangement is checked against the concept's: order, place across the view and the way a thing faces (the owner, 2026-10-21). Creator data wins: a thing the creator already planned (the ship's floor plan, held by the hangar) is laid from his plan as given, at its own size, where and the way the drawing shows it, never reinvented; a run of shelving or crates is one item with its count (the owner, 2026-10-21). A parent scene's plan also splits it into the shapes of its child scenes, each with its outline, doors and the inventory row of the parent scene it stands in (or the parent scene's own walls); who the child scenes are is decided there, not in a hand-kept list (the owner, 2026-10-21), and a child scene's concept is drawn only once that plan is made, sent its shape on it. _Avoid_: layout (the inventory's laid spots), floor plan (the owner's word for the same thing), blueprint.
- **prop pipeline** — the one channel every object and shell piece is made through (the owner, 2026-10-20, #19); its gates decide what more a model needs (a code body for a big object, code only on a named failure). The route's picture-to-3D branch: close-up, Pixal3D in a cloud batch, closed into a solid, triangles by size, straightness check. The same picture-to-model step turns a whole concept into a scene's rough model. _Avoid_: generator, AI model step.
- **layer adapter** — what a layer that needs models adds around the prop pipeline, which still makes every model: its own inputs (which rows, close-up wording, poses or growth stages) and its own steps and checks after the model (rigging and motion for people, joints and paths for rigid moving things, growth for plants). Terrain is a model layer too: its concept goes through the prop pipeline as its rough model, then close-ups of its detail areas, the same shapes-first loop as a building. A layer without models (light, sound, sky, films) has its own route instead, under the same batch rules (the owner, 2026-10-20). _Avoid_: plugin, branch, custom pipeline, side route.
- **parts check** — the rule that routes a kind: the prop pipeline for every object and shell piece (the owner, 2026-10-20, #19); nothing is built in code as a fallback (the code fallback, its sorter and its failure record removed 2026-10-22). _Avoid_: sorter (the retired tool that applied it), shape rule.
- **surface library** — the set of rule-based surfaces (ProcFunc recipe variants, coloured from palette tokens, wear and seed as settings) every part of every piece is painted from; models and code give shape only. Every old surface was retired on 2026-10-21 (the owner: "a chance of contaminating with old is not worth it"): `data/library/materials.json` holds the method alone (recipes' defaults, wear levels), and each scene's surfaces are made fresh from its design by its `surface-library` row (one recorded ask on its locked concept, scene palette and object kinds), before anything of it is listed or baked. _Avoid_: material library, texture set, trim sheet.
- **finish map** — a flat-colour copy of a model's close-up: the same outline and framing, every finish one solid label colour on a plain background, each label tied to one surface of the surface library; used to split the model into parts by finish. _Avoid_: label map, segmentation mask, colour map, part map (a part map shows the split itself).
- **room wear** — the one wear setting a room's surfaces share, with wear from a cause (edges, feet, drips). _Avoid_: weathering, dirt pass.
- **scene palette** — the palette tokens a scene's surfaces are painted in, each a name and a colour the concept shows (coined fresh, never the old game's tokens), with its room wear (level, dirt and the token its dirt is drawn in), read from its locked concept by one recorded ask a scene (the finish route's `finish-route-palette` row; no rule reads either off the picture's pixels); its surface library is made in these tokens, and the finish route offers that library filtered by it. Never a hand-kept list per scene. _Avoid_: look (a person's on the people line, a style group's in place.json), place materials, scene materials.
- **walkable reference** — the optional stage that turns a locked concept into a walkable whole-room reference for later stages; never shipped, and not the rough model (that is the loop's own step, made by the prop pipeline). World Labs Marble (the product's own name, kept) in our runs; never compared with another model. _Avoid_: world step (the older word), plan world (2099's), world model.
- **review tools** — what SCORE gives the creator to judge a scene: pages with each stage's outputs side by side, before and after shots from the same cameras, in-engine walkthroughs and every check's result. How the creator judges with them is the creator's own. _Avoid_: blind pick, vote, approval gate.
- **creator cockpit** — the one signed-in web page the creator runs SCORE from: his environments, each split by engine, then style, then scene, layer and step, where he inspects outputs, asks for changes, advances steps, buys his basket and launches work against his stop. It reads the runner and the review tools and judges nothing itself. _Avoid_: dashboard, admin panel, UI, control panel, web app.
- **basket** — what the creator buys in the creator cockpit, item by item: each item is one change, and opens to details that are free and fast to make (before and after from the same cameras, a 3D look, what moves and its price) and show what buying it would change; buying the basket is the creator's one money yes. The owner's rule of 2026-10-19. _Avoid_: proposal (retired as the creator's word; the cockpit's `proposals/` code makes an item's details), shopping list, cart, changes to buy, order.
- **batch** — one shot of paid work the creator said yes to, at any layer: one spend estimate and one ETA given before it starts; the creator's yes to that estimate is the only spend decision, and the batch's stop is its own high estimate plus a 10% buffer, never a separate figure he sets (the owner, 2026-10-20); every job run once, no reruns or retry loops inside it. Its checks only sort each output into a success or a named failure mode; a failure becomes a gap, and any new spend on it is a new ask: a Buy while the batch is unfinished is another **try** of the same batch, not a new batch, whatever design edits came between (the owner, 2026-10-25 and 2026-10-26). It starts only from approved designs and runs from there to a finished scene. All the risk work happens before the batch, free: predictions and preparations that make it right the first time (the owner, 2026-10-20). _Avoid_: run (alone), job (one task inside a batch), retry, loop.
- **try** — one Buy of a batch: the first Buy starts it, and each Buy while some of its rows failed or never ran tries it again, whatever design edits came between: fixes made to finish it are part of it ("Batch 1, try 2"; the Buy page says "Retry Batch 1"); a new batch begins only once every row it planned was made (the owner, 2026-10-25: "its the same batch, ur just retrying a failed part of it; it will become a mess if we split after fail"). A Buy whose run was stopped before it began (before its first heartbeat, as one waiting for machines) is a relaunch, not a try. Its rows, spend and problems count across its tries; its ETA is the try's own; its money is the batch's one budget, every try drawing from it, a retry inside what is left needing no new ask (the owner, 2026-10-26: "those budget asks should become per batch tho, not per try"). _Avoid_: attempt, rerun, second batch (for a try).
- **warm pool** — the graphics cards one Buy holds warm from its start to its end, rented once for the whole batch and shared by every cloud step, each card taking the next queued job of any kind (the owner, 2026-10-23: "i would use like 10 gpus but warm for the entire batch"). It grows beside the batch, which starts on its first warm card (the owner, 2026-10-23: "the buy run can just start as soon as one is warm, in the background u just try collecting more till 10, so its sepperate"); its idle time is the batch's own cost. It also holds a few processor machines, which its Blender renders and bakes take as readily as a card, whichever is free first (the owner, 2026-10-23); a model's job takes a card only. _Avoid_: card pool, fleet (Pixal3D's own machines in one step), cluster (the Kubernetes path), reserved capacity.
- **basket item** — one change in the basket (a fix branch for one scene), priced by the runner, with its free details. _Avoid_: proposal, card, line, offer.
- **film script** — a film's ordered list of segments on one timeline, kept as data, one file a film (`data/films/<film>.json`): each segment says what it shows (the environment, a scene, a layer, a part or piece), its cut type (walk-through, orbit, hero still, exploded view, isolate, layer focus, layer split, step card, before and after, title or text card, screen take, physics animation, scale zoom; any of them may carry a picture-in-picture: a concept, plan or inventory shown in a corner), its length in seconds, its transition and its sound. The creator writes it in the creator cockpit and plays it there for free on the scenes' 3D web copies and existing films; it compiles to render items (the frames still to make, the films reused) priced before anything is bought. A demo film is a sales trailer for the environment, so the script gives the finished scenes the time. The film is a design step of its own, after the scenes and before Buy (the owner, 2026-10-21): every environment opens on its default film, the owner's script for environment 1 (the app's steps, then one unbroken shot from the setting down into the top scene's rooms) filled in from its own scenes, which the creator changes and then locks like a concept; the lock is his approval, the batch films the locked script, Buy waits for it, and he may unlock it until a batch is bought on it. _Avoid_: storyboard, shot list, edit decision list, EDL, cut list, timeline (alone).
- **screen take** — a film segment that is a scripted recording of a real creator cockpit page (cursor path, clicks, highlights, a short caption), recorded the same way every time from the page as it stands. _Avoid_: screen recording, screencast, UI capture.
- **scale zoom** — a film segment that is one unbroken camera path down through an environment's layers (physics, world, site, scene, room), so a shot carries on where the last one ended; between top scenes it goes on over the ground from the site before, or out from its world across the physics to the next body and down again. _Avoid_: zoom transition, fly-in.
- **physics animation** — a film segment that plays the environment's physics (its bodies moving on their orbits, a plot's sun path) as a short clip at a chosen speed; its cut id is still `setting-animation`. _Avoid_: setting animation, orrery, solar system animation.
- **picked viewpoint** — a view the creator saved while walking a scene in the viewer (eye, aim, fov, a name), kept in `data/review/<place>/viewpoints.json`; a scene's films start from its picked viewpoints when it has any. _Avoid_: bookmark, saved camera, pick (alone: a pick is a model the creator chose for a row).
- **capability class** — what a cloud job needs from a machine, named without a provider: `gpu-<GB>gb` (one card with that much memory), `gpu-<GB>gb-x<N>` (N such cards), `cpu-<cores>c-<GB>gb` (a processor machine). Runners ask for classes; the cloud backend maps each to its own machine types. _Avoid_: machine type, instance type, card type (these are a provider's names).
- **parked machine** — a machine kept after its run (its files removed, its set-up kept) for the next run of the same kind to take instead of renting (`tools/cloud/park.py`): a processor machine billed by the started hour until 5 min before its paid hour ends, a card for its kind's measured cold start (at most 10 min). Never idle past that. _Avoid_: warm machine, kept machine (a card held for a Buy is in its warm pool).
- **cloud backend** — one cloud provider behind the framework's provider interface (`tools/cloud/provider.py`), holding that provider's machine types, zones, prices, secret store and self-delete. Scaleway is the current one. _Avoid_: cloud (alone), provider module, Scaleway (for the interface).
- **character** — a person or animal in a scene, made from the scene's data, rigged and playing a clip: a skinned UsdSkel asset in the scene's stage. _Avoid_: NPC, actor, avatar, agent (an agent is a coding agent).
- **sim body** — a character's physical twin on Newton, part of the people layer: driven by the character's SOMA segment rotation matrices through a rotation solver (no scaling, no per-person setup), its mass from SOMA segment volumes, standing in the scene's physics so its ground forces come from contact (owner, 2026-10-27, #56). _Avoid_: ragdoll, physics avatar, musculoskeletal model (a sim body has no muscles yet).
- **video clip** — a body's motion captured from a video the creator uploads (`{home}/design/clips/<clip>.mp4`). SAM 3D Body reads the person in every frame, and the motion is retargeted onto SOMA-X's rig, the one every person's body plays (`score/stages/video_clips`, `tools/characters/clips`, #52). It is kept beside Kimodo's generated clips, which are made from a sentence. _Avoid_: mocap, recording, animation.
- **cast** — the record of a scene's characters: who is there, how many, where, doing what, and why each is there; nothing is placed that is not an entry. Read from the scene's locked design (#26): each people row of its scene inventory a look of the shared people line, one look a person, a crowd one far look (`data/people/rows.json`); the old game records (`data/characters/`) no longer say who. _Avoid_: spawn list, population, NPC list.
- **crowd** — retiring (owner, 2026-10-27: "the framework is about simulation, not making a minimal optimized env"; every person becomes a character with its own sim body, #56). Until then: many copies of one cheap character body in a few clips, phases and palettes of clothes, laid as one instancer; anybody within reach of the viewer is a character of their own instead. _Avoid_: extras, background people, swarm.
- **stage** — one fixed step of the route, with a stated input and output, gates and a review page (concept, plan, inventory, layout, assembly, settle, the layers, complete; close-up, shape, parts, surfaces per object). A row of the stage table in `score/stages`. _Avoid_: step (alone), phase, task.
- **runner** — SCORE's engine, the `score` command: it walks the stage table for an environment, works out each node's key from its code and inputs, finds what is already made and accepted in the store, prices and times what is missing, runs the rest (paid nodes on rented cloud machines, in a batch the creator said yes to), judges each output with its gates and records it. It decides nothing about taste; the creator cockpit shows what it reports. _Avoid_: pipeline (alone), orchestrator, scheduler, engine (the game engine).
- **node** — one stage for one scene (`assembly@hangar`), or for the whole environment (its grain is still called `world` in the keys); what the runner keys, makes, judges and accepts. _Avoid_: job (a job is a cloud run), target, asset.
- **finish record** — what a node's run leaves in the store: its key, output, every input's hash, its code version, commit, seed, parameters, machine, time and cost. No record counts as not run. _Avoid_: log, manifest, run info.
- **gate** — a stage's check between it and the next: it answers pass, fail or unknown with measures and a reason; unknown blocks like fail, and missing evidence is unknown. _Avoid_: test, validation, guard (a guard is a hook).
- **accepted output** — the output of a node that stands accepted; the only one later stages read. The runner accepts an output by itself when every gate passed and no score got worse (an automatic accept, its record says so); the owner may reject any accepted output, which moves it back to the one accepted before and makes every later node that read it stale, or accept a worse one with his reason. _Avoid_: canonical, latest, current take, approved.
- **clearance** — the runner's leave for one paid run of a node: given when every gate on its inputs passed and they stand accepted, the month's books are known, and its batch's stop (or a benchmark grant) has room for its forecast; there is no month's ceiling (owner, 2026-10-20); kept in the store, and the only thing besides the owner's override that lets a rent point spend. _Avoid_: spend yes (that is the owner's override), approval, budget.
- **unverified seed** — an old output brought into the store as a stage's output (hashed, its origin shown) that no gate has judged yet; never accepted until its stage reruns or checks it. _Avoid_: legacy output, baseline, import.
- **contract** — a stage output's schema, version and units (metres, seconds, degrees, Y up), stamped into the output as `contract.json`, checked by the stage that makes it before it is stored and by every stage that reads it. _Avoid_: format, spec, interface (an interface is a module's way in).
- **quality score** — a library entry's 0 to 100, made of named parts that a scoring system of its own kind measures free and locally (a model's geometry, finish and likeness; a sound's prompt match, loudness and clipping), 50 being a gate's line where a gate measures the part; an assessment for choosing what to refine, never a gate. _Avoid_: score (alone: the framework's name), rating, grade, quality (alone).
- **item preview** — a library entry shown live and free on the cockpit's item page from what the library already holds: its web copy turning in the three.js viewer under the viewer's studio light, a surface on a sample ball, an effect or a copy's motion playing in place, a sky or a scene's lamps, a sound's takes with a play button. Never a paid render: library items are never rendered as preview videos (owner, 2026-10-22: the retired `library-clips` row was "waste"). _Avoid_: preview clip (the retired paid render), turntable render, preview render.
- **waiver** — the owner's word that one check of one node counts as passed under one key, with his reason; it ends when the key changes and shows on the review page and in status. _Avoid_: override, exception, skip.
- **gap** — something a scene still lacks or that fails a check, shown in its OpenUSD scene: a scene inventory row with nothing made for it, a made object that fails a gate, a route step the scene has not been through, or a lost input. What a scene needs comes only from its concept and the scene inventory drawn from it. A gap is **open** (still to be made or fixed; priced and in the basket) or **accepted** (the creator decided to ship with it, written in `data/checks/gaps/<place>.json` with who decided, when, why and the measured faults; the completion gate lists it but does not block on it; never a loosened gate). A **batch gap** is accepted by the creator's yes to the batch instead: a take a paid step failed inside the batch (its close-up, its Pixal3D job, its finish list, its bake, its recheck), named by that step's output with the failed check and its faults (`score/stages/batch_gaps.py`), left out of the rest of its scene's line and listed by the completion gate, never a stop and never a per-gap accept; fixing it is a new batch. The owner, 2026-10-20: one word for both, in code, data and the cockpit too (#41). _Avoid_: hole, named gap, missing item, todo, waiver (a waiver passes a check), known issue.
- **complete** — a scene's status when every requirement of its completion gate passes and it has no gap. _Avoid_: done, finished, shipped.
- **complete apart from accepted gaps** — a scene's status when its accepted gaps are the only requirement that fails: the gate lists every gap with its numbers and who decided it, and the run passes. _Avoid_: mostly complete, complete with gaps, partly done.
- **NOT complete** — a scene's status when any other requirement fails or is unknown. _Avoid_: incomplete, failed, blocked.
- **shell split** — the route's step between a parent scene's rough model and its child scenes: the parent scene's plan cut into the shapes of its child scenes (rooms, corridors, holds), each sized inside it, tiling its inside with no overlap and every one reached through doors; the stage `shell-split` (`score/stages/shell_split`), whose output every child scene's own route reads. _Avoid_: floor plan (the owner's word for a plan), room split, partition (the concept partition is the picture's), subdivision.
- **finish route** — the library-first way a model gets its finishes (owner, 2026-10-20): the model rendered from every angle a free coverage check needs, one batch answer a model giving its finish list (each finish first matched to a surface of the surface library with its settings: palette token, shine, seed; wear stays the scene's level) and a label for each colour region of each view, the model split by those labels voting across views (an unassigned face or views that disagree is a gap), each part given its surface, and one batch recheck against the close-up that only sorts pass or the named fault "no library surface fits". The scene lines' surface route since 2026-10-20 (#18); rows `finish-route-*` and `surfaces-parts`, `-paint`, `-bake`, `-check` in `score/stages/surfaces`. _Avoid_: paint pass, texturing, finish-map method (the earlier route, kept by the crops' and people's lines).
- **stand-in close-up** — what the finish route shows in place of a model's close-up when its own is not there: the model's own texture drawn from the front. Always named a stand-in; a recheck against it says so. _Avoid_: close-up (alone, for it), reference render, fake close-up.
