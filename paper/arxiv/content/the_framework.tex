\section{The framework}\label{the-framework}

An environment is one OpenUSD record. Each \textbf{scene} is one stage; a scene sits within its parent scene and holds its child scenes, referenced at the rooms its plan gives them, so opening a top scene opens everything below it. Each scene's layers stack in a fixed order: a slot for the creator's edit layer on top, then people, sound, light, motion, effects, crops, machines, physics, settle, ground and the base laid from the locked plan. Each object, one per real-world object, carries its kind, transform, collider and each part's library surface. The environment's \textbf{physics} is decided in its environment concept (EC): a plot of ground with a gravity and a sun path, one world, or a system of bodies that move one another, a real body taking its values from a cited table and an invented one given by its radius, mass, orbit and spin. The physics layer writes a scene's bodies, mass, joints and the gravity of the body it stands on in OpenUSD's physics schema, so any reader of that schema gets the same scene.

The creator works in the creator cockpit, one signed-in web page, where he locks the design, buys paid work and reviews what the framework reports. Below him, an environment is a table of stages read off its designs; environment 1's has 261 rows. A \textbf{node} is one stage for one scene (\texttt{assembly@hangar}) or for the environment, and one runner makes, judges and accepts every node. From an approved design everything runs without a further yes.

\textbf{Keys.} A node is made only when its key has no finish record. The key hashes the stage and scene, its code version, contracts, parameters and seed, the pinned model images, every file it reads and the accepted output of every node it reads. The code version counts only code that can shape the output; code that decides where and how a job runs changes what a run costs, never what it makes, and is in no key. An edit or a fixed fault moves only its own key and those after it, so only those steps run again. Outputs are kept by content hash, never overwritten.

\textbf{Gates and accepts.} Each gate answers pass, fail or unknown, with measures and a reason; missing evidence is unknown, and unknown blocks like fail. The runner accepts an output by itself when every gate passed and it is no worse than the one accepted before. Later nodes read only accepted outputs. The creator keeps four actions: reject an accepted output (every node that read it is then stale), accept a worse one with a reason, waive one gate for one key, and override the runner for one paid run. A store that refuses these records from an agent's process, and a hook, keep agents from them.

\textbf{Batches.} Paid work is bought as a batch with one estimate; the creator's yes sets the batch's budget across all its tries, and the money guards stop it there. Inside a batch every paid job runs once; a failed output becomes a batch gap that the completion gate lists. Every paid stage is priced from a unit cost measured on the ledgers; a stage with no measured run has no price, and its estimate is shown apart as a guess.
