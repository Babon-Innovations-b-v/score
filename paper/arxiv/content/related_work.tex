\section{Related work}\label{related-work}

\textbf{World models and one-shot world generators.} Genie learns an interactive environment from video and lets a user act in it frame by frame \citep{bruce2024genie}; Genie 3 does so in real time from a prompt \citep{genie3}. WorldGen generates traversable, editable worlds from text for standard game engines \citep{wang2025worldgen}; HY-World 2.0 generates one splat or mesh world from text or a picture \citep{hyworld2}; WorldAct decomposes such a monolithic world into objects after the fact \citep{hu2026worldact}; WorldSculpt composes per-object meshes from grounded video \citep{niu2026worldsculpt}. Commercial world generators such as World Labs' Marble build one world per request from text, pictures or a panorama \citep{marble_docs}. SCORE uses no world model as its output. A world generator can appear in it only as an optional step that produces a reference for later stages (Section 3.10).

\textbf{Agents that build scenes.} Holodeck has a language model write spatial constraints that a solver satisfies, with objects retrieved from a library \citep{yang2024holodeck}; LayoutGPT plans layouts with a language model \citep{feng2023layoutgpt}. SceneCraft has an agent write Blender code \citep{hu2024scenecraft}, recursive code world models build a scene as a program and compare renders with a reference \citep{li2026rcwm}, WorldClaw runs render-checking agents over a terrain \citep{guo2026worldclaw}, and AutoUE has agents write gameplay code in Unreal Engine \citep{yin2026autoue}. 3D-RE-GEN turns one picture of a room into separate objects through detection, per-object generation and placement \citep{sautter2025regen}, and SceneConductor adds a planner agent that finds inconsistencies after placement \citep{kim2026sceneconductor}. LEGO-Anything is the closest in spirit: a coding agent writes and revises Blender code to rebuild a scene from one picture, and its authors find three recurring failures, ``weak scene initialization, regressive edits during iteration, and unreliable self-evaluation'', which they address with tools rather than training \citep{li2026lego}. SCORE takes the same position, that an agent should be given grounded tools in place of its own judgement, but aims at worlds that do not exist yet, built to a person's picks.

\textbf{Procedural generation and surfaces.} Infinigen generates whole natural worlds from randomized rules, with materials as their own generators \citep{raistrick2023infinigen}; Infinigen Indoors adds a constraint language and solver for arranging rooms \citep{raistrick2024indoors} and articulated assets \citep{joshi2025articulated}. ProcFunc gives these generators a function-oriented Python interface on which vision-language models make far fewer coding errors when writing procedural materials from scratch \citep{raistrick2026procfunc}. MatFuse generates materials from palettes, sketches and pictures \citep{vecchio2023matfuse}. Studios have long shared surfaces across pieces rather than texturing each one \citep{olsen2015trim}, and build environments from modular kits with strict footprints \citep{burgess2013skyrim, ldb_modular}. SCORE's surface library is written in ProcFunc on Infinigen's shader code.

\textbf{Parts and style.} PartCrafter generates a mesh as several parts from one picture \citep{lin2025partcrafter}; OmniPart, HoloPart and SAMPart3D plan, complete or segment parts \citep{yang2025omnipart, yang2025holopart, yang2024sampart3d}; Point2Part partitions a shape from point prompts \citep{tsui2026point2part}. Keeping one style across generated objects is named as open: a survey of production-ready 3D generation notes that no large dataset carries coherent lighting, style descriptors or compatible materials across assets \citep{wu2026production}, FlowScene notes that retrieval-based composition ``often fail{[}s{]} to enforce scene-level style coherence'' \citep{yang2026flowscene}, and Hunyuan3D Studio fixes a style at the picture before any 3D is made \citep{lei2025hunyuanstudio}. SCORE holds style by taking it away from the generated models altogether: they give shape only, and every surface comes from one library.
